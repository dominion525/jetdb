# Internal Structure of MSysQueries

Findings from investigating how saved queries are stored in Access database files (.mdb/.accdb).

## Overview

Saved query definitions are stored in the `MSysQueries` system table. Each query consists of multiple rows, linked by `ObjectId`. Query names are not stored in `MSysQueries`; they are obtained from the catalog (`MSysObjects`) via `ObjectType=5` (Query) entries.

## Column Structure

| Column Name | Type | Description |
|-------------|------|-------------|
| ObjectId | Long | Query ID (links to MSysObjects.Id) |
| Attribute | Byte | Row type (see below) |
| Order | Binary | Sort order within the same Attribute |
| Name1 | Text | Table name, parameter name, etc. (depends on Attribute) |
| Name2 | Text | Alias, etc. (depends on Attribute) |
| Expression | Memo | SQL expression (column expression, JOIN condition, WHERE clause, etc.) |
| Flag | Int | Flag value (depends on Attribute) |
| LvExtra | Long | jetdb reads it as the size of a Text parameter (Attribute=2, Flag=10). Jet4 and later only; Jet3 (Access 97) has no LvExtra column |

## Attribute Constants

| Value | Constant Name | Description | Flag Meaning |
|-------|---------------|-------------|--------------|
| 0 | (Header) | Query header row | Query flags (often 0) |
| 1 | ATTR_TYPE | Query type | QueryType value (see table below) |
| 2 | ATTR_PARAMETER | Parameter definition | Parameter data type |
| 3 | ATTR_FLAG | SELECT flags (DISTINCT, etc.) | Bit flags |
| 5 | ATTR_TABLE | FROM clause table | - |
| 6 | ATTR_COLUMN | SELECT clause column | Column flags |
| 7 | ATTR_JOIN | JOIN condition | JOIN type |
| 8 | ATTR_WHERE | WHERE clause | - |
| 9 | ATTR_GROUPBY | GROUP BY clause | - |
| 10 | ATTR_HAVING | HAVING clause | - |
| 11 | ATTR_ORDERBY | ORDER BY clause | - |
| 255 | (Terminator) | Query terminator marker | - |

## QueryType Values (Flag of ATTR_TYPE)

| Value | Constant Name | Access Query Type |
|-------|---------------|-------------------|
| 1 | Select | Select query |
| 2 | MakeTable | Make-table query |
| 3 | Append | Append query |
| 4 | Update | Update query |
| 5 | Delete | Delete query |
| 6 | Crosstab | Crosstab query |
| 7 | Ddl | Data definition query |
| 8 | Passthrough | Pass-through query |
| 9 | Union | Union query |

## Embedded Queries (~sq_ Prefix)

SQL set as RowSource or RecordSource on form and report controls is internally saved by Access in MSysQueries with names prefixed by `~sq_`. These are not queries explicitly created by the user; they are automatically generated by the Access form/report designer.

### Naming Convention

```
~sq_<type><form/report name>[~sq_<type><control name>]
```

Type codes:

| Code | Meaning | Example |
|------|---------|---------|
| c | Control RowSource | ~sq_cF_請求書一覧~sq_ccmb_クライアント名検索 |
| d | Report control DataSource | ~sq_dR_請求書~sq_dクライアントID |
| f | Form/subform RecordSource | ~sq_fF_クライアント情報 |
| r | Report RecordSource | ~sq_rR_請求書 |

### Missing ATTR_TYPE

Embedded queries often lack the ATTR_TYPE (Attribute=1) row. A typical composition consists only of Attribute=0 (Header), 3 (FLAG), 5 (TABLE), and 255 (Terminator).

Measured values from a database in real use:

  Total query count (Query entries in MSysObjects): 227
  Queries with ATTR_TYPE: 43 (all user-defined queries)
  Queries without ATTR_TYPE: 184 (all ~sq_ embedded queries)

### Handling in jetdb

`queries list` / `queries show` target only user-defined queries. Queries without an ATTR_TYPE row are handled as follows:

- Name starts with `~sq_` → Skipped as an embedded query
- Name does not start with `~sq_` → Falls back to QueryType::Select

The latter case accommodates user-defined queries that lack an ATTR_TYPE row, such as those in formPropTest.accdb.

## Special Case: formPropTest.accdb

In formPropTest.accdb, all 3 queries lack an ATTR_TYPE row (only Attribute=0, 3, 5, 255 are present). The cause is unknown, but since similar files may exist in production environments, they are handled via the Select fallback. In queryTestV2007.accdb and queryTestV2010.accdb, ATTR_TYPE is present as expected.
